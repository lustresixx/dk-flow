# 平台化路线图

> dsh-ace-harness 的目标不是停留在本地插件：它是一个**平台级 workflow 产品内核**——多租户、可调度、可观测、可治理、可计量、可扩展，能够部署到平台为大量用户服务。本文档盘点现状、列出平台化缺口与优先级，作为后续迭代的路标。

## 现状盘点

### ✅ 已具备

| 领域 | 能力 |
|---|---|
| 核心引擎 | 状态机引擎（状态/步骤/并行段/join）、二元 success/fail 流转（AI 判断，兼容旧 pass/conditional_pass）、熔断（maxTransitions / maxSelfTransitions）、子工作流嵌套（深度上限） |
| 节点类型 | AI 步骤（DSH 子代理 + 角色 + 工具过滤）、快速 LLM（单轮直调）、脚本（JS 沙箱 / Python 子进程 / scriptFile 三级解析）、子工作流 |
| 多智能体 | 13 个内置角色 Agent（defender/attacker/judge/supervisor 四队）、红蓝对抗评审、7 个内置模板、7 角色接力评审 |
| 交互入口 | `/workflow` 斜杠命令族、`workflow_list` / `run_workflow` / `workflow_manage` 模型工具、斜杠菜单选择器、缺参弹卡询问（工具路径）、运行时参数表单（工作台） |
| 治理与恢复 | 每步持久化 + 断点恢复、崩溃归一化（10 分钟 stale → crashed）、人工审批门、无匹配人工决策点、supervisor 检查点（风险自适应）与评分、经验沉淀、Git baseline、审计日志 |
| 平台控制 | 步骤自动重试（指数退避、只重试瞬时错误）、步骤级超时、运行并发上限、停止按钮、wait=true 取消回合自动转后台 job（不丢运行）、运行保留（stale 归一化） |
| 可观测（基础） | 实时流式侧边栏（拓扑图 + 每步输出）、运行记录页运行时拓扑图（状态着色 + 执行路径加亮）、attempts/failedStates 显式呈现 |
| API（基础） | REST：state / workflows（CRUD）/ instantiate / run / stream / stop / assets；插件 Config（provider、model、超时、pythonCommand、并发等） |
| 脚本与技能目录 | 工作区 `.ace-workflows/scripts/` 收集目录 + 内置脚本库 + 三级解析 + `/workflow scripts`；`$DSH_HOME/skills/ace-workflow/` skill 自动安装 |

### ❌ 缺失（平台化需要补的）

#### P0 —— 平台 MVP（多租户上线前必须）

1. **认证与多租户隔离**
   - 现状：运行按工作区（workspace 路径）隔离，恢复授权仅校验 parentSessionId；无用户/组织概念
   - 需要：用户身份注入、租户/组织边界、运行与工作流按租户隔离、跨租户访问控制、API 鉴权（token/会话）
2. **运行配置快照**
   - 现状：RunState 只记 `configFile` 引用；文件被改/删除后旧运行无法恢复、拓扑图降级
   - 需要：启动时把完整 workflow 配置快照进运行记录（或内容哈希 + 版本引用），resume/展示永远可重建
3. **持久化格式版本化**
   - 现状：`state.json` 无 schema 版本，字段演进靠"向后兼容"
   - 需要：显式 `SCHEMA_VERSION` + 迁移器；旧格式要么迁移要么明确拒绝
4. **安全边界**
   - 现状：脚本是"信任配置"约定（node:vm 非安全边界、Python 子进程无沙箱、preCommands 直接执行）
   - 需要：脚本/命令执行策略（允许/审批/沙箱）、密钥注入与脱敏（日志/结果里出现 key 一律打码）、路径越界防护补齐、资源上限（内存/CPU/时长）
5. **计量与成本基础**
   - 现状：子代理的 token 用量在各自 session 里，运行记录没有记账
   - 需要：每步/每运行的 token 用量、成本、耗时写入 RunState；按租户汇总

#### P1 —— 生产化

6. **调度与触发**：cron 定时、webhook / git 事件 / API 事件触发、失败自动重跑策略
7. **配额与限流**：租户级运行并发/日运行数/token 预算配额，超出即排队或拒绝
8. **可观测升级**：结构化指标（Prometheus）、运行 trace（每步 span）、告警（运行失败/超时/熔断）、审计查询接口
9. **API 硬化**：版本化路由（/v1/...）、分页（runs/workflows 列表）、幂等键、OpenAPI 文档、错误码规范
10. **部署形态**：独立 server 模式（不带 DSH GUI）、Docker 镜像、compose/helm、执行器队列化（运行交给 worker 进程/节点，横向扩展）

#### P2 —— 生态

11. **协作**：工作流共享/发布（模板市场）、RBAC（编辑/运行/管理）、多人审批链
12. **扩展点**：自定义节点类型注册、出站连接器（通知 webhook、制品存储、IM）、模型路由策略与降级链
13. **开发体验**：工作流 dry-run / 单步调试、CI 校验（lint/validate 门禁）、独立 CLI / SDK、示例数据与单测模板

## 分阶段计划

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| **P0 平台 MVP** | 多租户隔离 + 鉴权、运行配置快照、持久化版本化、安全策略（沙箱/密钥/脱敏）、计量基础 | 多个租户在同一部署上互不可见地运行工作流；旧运行永远可恢复可展示 |
| **P1 生产化** | 调度触发、配额限流、指标/告警、API 版本化 + OpenAPI、容器化部署 + worker 扩展 | 平台可对外提供服务：无人值守调度、用量可控、故障可观测 |
| **P2 生态** | 协作/市场、扩展点、SDK/CLI、调试工具 | 第三方可贡献模板、节点、连接器；开发者可本地开发调试 |

## 每次迭代的验收基线

- 新增持久化字段必须走版本化 schema（P0 落地后）
- 新 API 必须有对应测试 + 文档条目；破坏性变更走版本化路由
- 任何可能进入日志/结果的敏感值必须脱敏
- 平台行为（调度/配额/计量）全部可配置、可在测试中关闭
